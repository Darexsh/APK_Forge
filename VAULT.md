# Vault Directory

APK Forge expects a separate private repository for app data, credentials,
generated state, and release assets. This repository is the vault.

## Directory Structure

```text
vault/
  .env
  apps.json
  catalog.json
  docs/
    archive-apks-release.md
    patched-apks-release.md
    source-apks-release.md

  keystore/
    public.jks

  sources/
    example-app/
      Example_v1.2.3.apk
```

## Git State

Do not commit these files as they are published from Forge to release asset:

```text
.env
sources/**/*.apk
sources/**/*.apkm
sources/**/*.apks
sources/**/*.xapk
tmp/
```

## File Roles

`apps.json` is desired state. It lists the apps Forge should manage and where
their source packages and patch bundles come from.

`catalog.json` is published state. It lists APKs that were actually produced,
uploaded, and made available to clients.

`docs/source-apks-release.md` is the release body used for the private
`source-apks` release.

`docs/patched-apks-release.md` is the release body used for the private
`patched-apks` release.

`docs/archive-apks-release.md` is the release body used for the private
`archive-apks` release. Archive APKs are stored as-is and are not patched by
Forge.

Release body files may contain this marker block:

```md
<!-- APK_FORGE_ASSET_LIST_START -->
<!-- APK_FORGE_ASSET_LIST_END -->
```

Forge updates only the generated asset list inside those markers.

`.env` should define `GITHUB_TOKEN` for private release access.

`keystore/public.jks` is the default signing key path. Commit this file only
when it is intentionally shared signing material.

`sources/<app-id>/` contains one manually supplied source package before it is
published to the private `source-apks` release.

`tmp/` is Forge workspace/cache output. Forge creates it when running; it does
not need to exist in a fresh vault checkout.

## GitHub Releases

The vault repository should use stable release tags:

```text
source-apks
patched-apks
archive-apks
```

`source-apks` stores manually supplied source packages when they should live as
private release assets instead of git files.

`patched-apks` stores signed APKs generated by Forge.

`archive-apks` stores APKs that should be published without patching, such as
owned or internally developed apps.

## Source Package Command

From the Forge repository:

```bash
python -m apk_forge source publish \
  --all \
  --config /path/to/vault/apps.json \
  --vault-root /path/to/vault \
  --repo owner/private-vault \
  --body-template /path/to/vault/docs/source-apks-release.md
```

This scans `sources/<app-id>/`, uploads changed source packages to the private
`source-apks` release, and updates `apps.json` with release asset metadata and
SHA-256 values.

Use `--skip-upload` to update `apps.json` locally without contacting GitHub.
Use `--remove-missing` with `--all` when deleting an app from the vault.

After a successful source publish, commit and push `apps.json` in the vault
repository.

## Sync Command

From the Forge repository:

```bash
python -m apk_forge sync \
  --config /path/to/vault/apps.json \
  --vault-root /path/to/vault \
  --workspace-root /path/to/vault/tmp \
  --catalog /path/to/vault/catalog.json \
  --repo owner/private-vault \
  --body-template /path/to/vault/docs/patched-apks-release.md
```

`sync` builds, signs, publishes, and updates `catalog.json`.

On repeat runs, unchanged apps are skipped. Use `--force` to rebuild and reupload
everything enabled.

After a successful sync, commit and push `catalog.json` in the vault repository.


## Minimal apps.json

For source packages stored as private release assets:

```json
{
  "schemaVersion": 1,
  "apps": [
    {
      "id": "example-app",
      "name": "Example App",
      "packageName": "com.example.app",
      "enabled": true,
      "mpp": {
        "owner": "example-owner",
        "repository": "example-patches",
        "release": "latest"
      },
      "sourceApk": {
        "type": "githubReleaseAsset",
        "repository": "owner/private-vault",
        "release": "source-apks",
        "asset": "Example_v1.2.3.apk",
        "sha256": "0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef"
      }
    }
  ]
}
```

For source packages stored inside the vault working tree:

```json
"sourceApk": {
  "type": "vault",
  "path": "sources/example-app/"
}
```

When `path` points to a directory, that directory must contain exactly one
supported source package:

```text
.apk
.apkm
.apks
.xapk
```
